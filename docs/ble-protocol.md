# 蓝牙 UART 命令协议

依据 [ble_uart_buttons.sv](../fpga/rtl/ble_uart_buttons.sv) 和冻结顶层的实例参数整理。此协议位于蓝牙模块到 FPGA 的 UART 一侧，不规定蓝牙广播名、服务 UUID、配对口令或手机应用界面。

## 链路

| 参数 | 值 |
| --- | --- |
| 模块时钟 | 150,000,000 Hz |
| 波特率 | 115200 |
| UART 格式 | 8 数据位、无校验、1 停止位，空闲高 |
| 帧格式 | `0xA5` + `CMD` + `CMD` 的 8 位按位取反 |
| 命令范围 | `0x01` 至 `0x03` |
| 命令输出 | 对应事件脉冲，一个模块时钟周期 |
| FPGA 应答 | 未实现；顶层 TX 固定为高 |

## 命令表

| 原始字节（HEX） | 模块输出 | 含义 |
| --- | --- | --- |
| `A5 01 FE` | `key_start` | 启动/操作事件，后续含义由既有控制逻辑决定 |
| `A5 02 FD` | `key_style` | 风格切换事件 |
| `A5 03 FC` | `key_view` | 视图切换事件 |

三类命令与已有实体按键事件在顶层合并。不能通过本协议指定绝对风格槽位、读回状态、请求图像流或加载权重。

## 发送方式与超时

串口工具选择“HEX/十六进制发送”，一次发送完整的三个字节，不追加 CR/LF。比如输入 `A5 02 FD` 后按一次发送；不要在文本/ASCII模式下发送这串字符。

RTL 使用 `BIT_CYCLES=(CLOCK_HZ+BAUD/2)/BAUD`，默认值 1302。组帧超时阈值为 `BIT_CYCLES*40`，在等待下一个字节且没有 `rx_valid` 时累计，约 347.2 微秒。此值是接收组帧的超时间隔，不是整次按键操作或图像切换的耗时上限。因此三字节应在一次串口写入中连续发出，不能人工逐字节点击发送。

协议没有 ACK 或去重序列号。为了避免连续多次触发，调试时每次只发一个完整帧，观察画面后再发下一帧；持续按住 App 按钮时应由发送端控制重复发送行为。

## 异常处理

- 停止位错误会触发 `bad_frame` 并清空当前组帧状态。
- 非法命令、补码不匹配或等待超时会触发 `bad_frame`。
- 某些错误字节恰好为 `A5` 时，状态机会将它作为下一帧头重新同步。
- `bad_frame` 是模块输出信号，不是发回手机的错误响应。

本文只核对源码定义，本次归档没有进行串口回环、手机连接或实板重新测试。电气电平、蓝牙模块工作模式与实体接线需使用原团队已验证配置。
