# 使用说明

本说明分为已有设备演示和从源码恢复工程两种情形。当前仓库没有可下载位流、Flash 镜像或手机 APK；演示步骤以团队已烧录成功版本的原硬件为前提。

## 准备硬件

| 组件 | 核对内容 |
| --- | --- |
| Ti60F225 开发板及 IO 板 | 与团队成功版本的板型、连接和供电一致 |
| 摄像头及排线 | 与原系统型号、接口和排线方向一致；赛题推荐 SC431HAI，当前归档未附实物型号验收记录 |
| HDMI 显示器及线缆 | 能接收 1920 × 1080 @ 30 Hz，接板卡 HDMI 输出口 |
| 蓝牙串口链路/原手机控制端 | 使用团队已验证连接；本仓库给出 FPGA UART 侧协议，不包含 App 或蓝牙模块配置 |
| 电源与连接线 | 按板卡、屏幕及现有装配的已确认额定值使用 |

断电时检查摄像头排线、HDMI、IO 板和供电连接。外壳装配参照[装配与五金原说明](../mechanical/enclosure_v9/装配与五金说明.md)，不要凭外壳示意图猜测电气接线或端口电压。

## 已烧录设备的演示流程

1. 按团队现有接线接好摄像头、HDMI 显示器及电源，显示器选择对应 HDMI 输入。
2. 按团队已有上电流程启动，等待图像链路与处理通路就绪。
3. 用原设备的启动/操作按键事件或蓝牙 `A5 01 FE` 触发操作；该命令对应 `key_start`，具体启动/停止行为由原控制逻辑决定。
4. 用风格键或蓝牙 `A5 02 FD` 切换风格，观察中文 OSD 名称。顺序为漫画、阿凡达、热成像、像素动画、阴曹地府。
5. 用视图键或蓝牙 `A5 03 FC` 触发视图切换，按实际画面记录原图/风格图对比行为。当前归档没有附各视图状态的截图，不指定未经验证的默认布局。
6. 记录屏幕显示的 AI FPS 与 HDMI 输出时序，保留原始视频和对应版本。原说明中约 17.1 FPS 是 AI 处理速度，不是 1080p30 显示时序。

代码存在三类物理按键事件，但本版本未附完整引脚约束，因此不指定哪一个实体按键等于 SW0/SW1/SW2。应以团队原板标签和原工程为准。

蓝牙命令必须按原始十六进制字节发送，一次连续发送完整三字节，不要发 ASCII 字符串或附加回车换行。详细时序见[协议说明](ble-protocol.md)。UART TX 当前空闲为高，没有命令确认回包。

## 从代码开始

先运行[完整性检查](verification.md)，再阅读[FPGA 代码入口](../fpga/README.md)。需要重新综合或烧录时，先按[环境说明](environment.md)补齐原 Efinity 工程、约束、IP 和镜像；不能把 Verilog 网表直接作为下载文件。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 大网表或 STL 只有几行 | 是否拿到 LFS 指针；在仓库内运行 `git lfs pull` 后重做校验 |
| Efinity 打开 HDL 但无法形成可编译工程 | 是否缺工程 XML、SDC、引脚/外设与 IP 配置；四个 HDL 文件本身不包含这些材料 |
| 屏幕无信号 | 已验证镜像、供电、HDMI 输出端、线缆及显示模式 |
| 有原图但风格画面不更新 | 原通路就绪状态、启动事件、当前模式与 AI FPS；保留故障记录交给原工程维护者 |
| 蓝牙命令无反应 | 模块已连接、UART 接线与配置、115200/8N1、原始三字节及命令间隔；不要等待并不存在的 ACK |
| 风格名称暂时未更新 | 名称在帧开始锁存，并受处理就绪信号控制，不能据此独立判断整条链路故障 |
| 外壳试装干涉 | 核对 V9-P1、mm/100% 缩放、打印收缩、试配环和实际线缆/插头尺寸 |

复现故障时请记录版本和具体操作，不要先覆盖板上已验证镜像或用未知工程重烧。
